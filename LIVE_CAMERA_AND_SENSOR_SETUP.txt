AquaMesh MVP — live camera + two LoRa sensor nodes
==================================================

WHAT CHANGED
- Replaced the hero "Urban twin" schematic with the live camera stream.
- Added live raw telemetry cards for FLOOD01 (RAIN, SOIL, PRESS/HX710B) and
  GAS01 (MQ, DIST, MPU status), plus camera-derived river/drain/land state.
- The engine continues to show the existing risk zones, forward/backward
  chaining, Bayesian hypotheses, event timeline, sensor health and evidence log.
- Protocol parser now accepts PRESS from FLOOD01 v2.4 as the pressure/HX feature.
  GAS01 DIST and MPU=OK/ERR are already supported.
- TTGO firmware remains a transparent LoRa-to-USB serial receiver; it forwards
  the full payload and appends RSSI/SNR. It does not need to decode fields.

IMPORTANT INTERPRETATION
- DIST is a relative MPU6050 motion/oscillation score, NOT calibrated water
  velocity. Camera "water" state depends on learned baseline and labeled regions.
- The current vision model is baseline/color + optical-flow based, not a
  trained semantic segmentation model. Use controlled lighting and camera mount.
- Rain is used as corroboration for land risk; the camera detects visible wet
  area. Drain/rivermotion corroboration depends on camera region metrics and DIST.
- Remaining sensors and terrain values are still part of the existing engine;
  do not present simulated values as live readings. Use --sim only for demo.

STEP-BY-STEP (Raspberry Pi OS)
1. Extract this ZIP on the Pi, or copy the aquamesh-mvp folder to the Pi.
2. Install dependencies:
     sudo apt update
     sudo apt install -y python3-opencv python3-picamera2 python3-numpy python3-serial
3. Connect the TTGO USB serial port to the Pi. Identify it:
     ls /dev/ttyUSB* /dev/ttyACM*
   Typical port is /dev/ttyUSB0 or /dev/ttyACM0. Grant serial access if needed:
     sudo usermod -aG dialout "$USER"
   Log out/in after changing group membership.
4. Open firmware/ttgo_receiver.ino in Arduino IDE. Select the correct TTGO
   LoRa32 board and upload. Confirm frequency 433E6, sync word 0x12, and pins
   match your exact TTGO revision and the LoRa modules on both ESP32 nodes.
5. Flash the provided FLOOD01 v2.4 and GAS01 v2.1 node sketches (your node
   firmware source) to the two sensor ESP32s. Ensure all radios use 433 MHz,
   sync word 0x12, and compatible wiring. FLOOD01 should send RAIN, SOIL and
   PRESS; GAS01 should send MQ, DIST and MPU. Node sketches are not silently
   rewritten by this package; check their GPIOs against your actual board.
6. From the project directory:
     python3 run.py --serial /dev/ttyUSB0
   Replace the port with the actual TTGO port. If camera is not connected:
     python3 run.py --serial /dev/ttyUSB0 --no-camera
7. Open http://<PI-IP>:8000 on a device on the same network. The camera feed and
   live sensor cards appear in the main panel. If you use a separate laptop
   browser, the stream is served by the Pi.
8. Calibrate the camera:
   - Use the dashboard camera stream and the vision region controls/API in
     aquamesh.vision's region tool if present in your version.
   - Select polygons for river, drain and land; avoid overlapping polygons.
   - Capture a dry baseline with no water present using the Learn baseline
     action/API. Then introduce water gradually and inspect state changes.
   - If no region calibration controls are exposed in the current dashboard,
     POST JSON region arrays to /api/regions; polygon points are normalized
     [x,y] values in the 0..1 range. Example:
       curl -X POST http://127.0.0.1:8000/api/regions \
         -H 'Content-Type: application/json' \
         -d '{"river":[[[0.1,0.4],[0.5,0.4],[0.6,0.7],[0.1,0.7]]],"drain":[],"land":[]}'
     Then POST to /api/learn to learn a dry baseline.
9. If the serial gateway cannot auto-detect the port, explicitly use --serial.
   To run a presentation without hardware use:
     python3 run.py --sim --scenario heavy_rain --speed 4  # simulated sensors + live camera (if available)
   This mode is simulated; it does not use real sensor packets or the live camera.
10. Run tests from project root:
      python3 -m unittest discover -s tests

PACKET FIELD COMPATIBILITY
- FLOOD01: FROM, PKT, STATUS, RAIN, SOIL, PRESS, UP, FW, C
- GAS01: FROM, PKT, STATUS, MQ, DIST, MPU, UP, FW, FLAGS (optional), C
- TTGO appends " | RSSI=-xx SNR=x.y"; do not append these values before CRC.
- The CRC covers the comma-separated payload before ,C=XX. Keep packet format intact.

KNOWN LIMITATION
The web dashboard currently provides live viewing and inference but not an interactive
polygon editor embedded in the main dashboard. Region setup is via the vision API
as described above. For the independent original calibration UI, see tools/waterwatch_original.py;
it may need Picamera2/OpenCV dependencies and should be run separately.
